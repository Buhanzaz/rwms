# RWMS — выполнение исправлений аудита

Основание: [полный аудит](rwms-work.md) и команда пользователя от 6 сентября 2026 года исправить находки, улучшать код и использовать агентов. Исходная ревизия перед исправлениями: `aa148f5aa5c7d347f6afca9ec67ba8991d897e21`.

UI и UX меняет только основной исполнитель. Он же проверяет весь diff, принимает результаты агентов и делает коммиты. По уточнённой команде пользователя одновременно исправляются четыре пункта: основной исполнитель ведёт сложную задачу, UI/UX и ревью; три агента получают по одному пункту аудита и непересекающиеся области файлов. Все работают в одном основном worktree; тяжёлые проверки и коммиты согласуются последовательно, завершённый пакет оставляет чистый git status.

По уточнениям пользователя: GPT-6 Astra для субагентов не используется; стоимость уменьшается короткими заданиями и повторным использованием уже собранных доказательств. CAD исключён из текущих работ, исходники сохраняются. По R-016 согласовано убрать нереализованные поля отдельных этапов из контракта, сохранив управление доступом через очереди.

Дополнительное прямое правило пользователя: устаревшие данные и код не требуют совместимости. Историческое поведение само по себе не является основанием сохранять поля, обходы или отдельные ветки реализации; решения опираются на действующие контракты и необходимое поведение продукта.

Порядок: High → Medium с зависимыми контрактами и consumers → Low и локальный рефакторинг → итоговая проверка. Новые подтверждённые проблемы добавляются отдельными строками; размер файла или само совпадение строк не требует механического переписывания.

Каждая завершённая строка содержит фактически выполненную проверку. Коммит, изменивший её статус, является записью завершения. Публикация не запрошена; исходные исправления и состояние уже запущенного runtime учитываются отдельно.

## Завершённые шаги

1. **R-095 — внешние credentials и безопасная ротация task-board.** Убраны fallback-секреты, оба сервиса отклоняют прежний секрет, auth проверяет точный контракт клиента и повышенную revision. При смене секрета сохранённые авторизации отзываются атомарно; повторный запуск сохраняет новые. Публичный issuer с development credentials блокирует запуск; существующие переменные окружения позволяют настроить безопасный публичный dev-профиль. Выполнены 86 auth и 14 task-board тестов, включая PostgreSQL rotation и HTTP token endpoint; ошибок и пропусков нет. Команды и XML проверены отдельным агентом, полный diff — основным исполнителем. Runtime не публиковался: новый секрет нужно согласованно установить у auth и task-board, а уже выданные JWT действуют до собственного `exp`.
2. **R-009 — канонический запрос тарифов Rental Manager.** DTO сериализует `rentalItemIds`, как требуют OpenAPI и request владельца. Обновлён существующий тест реального Retrofit/Moshi HTTP-запроса. Все шесть тестов `RentalPricingApiTest` прошли без пропусков; выполнена компиляция Android debug/test исходников. Проверка использовала Gradle 9.5.1, Java 17 и SDK 36; APK не публиковался.
3. **R-095 — дополнительная проверка префикса gateway.** `AuthGatewayPrefixIntegrationTest` использует loopback issuer, допустимый для его dev-credentials. Проверки discovery, однократного `/auth` prefix, forwarded redirect/login/logout и упакованного UI сохранены и прошли: 1/1 без пропусков. Общий результат R-095 — 87 auth и 14 task-board тестов; production guard не ослаблялся.
4. **R-136 — обязательная оплата сохранённого заказа до исполнения.** По уточнённому правилу пользователя убран допуск `NULL` из выборки планировщика и проверок исполнения. Только `CONFIRMED` разрешает включение сохранённого заказа в план, новую отгрузку, мебельные работы сохранённого заказа и подтверждение delivery slot в checkout. Редактирование черновика и его действующая складская подготовка замены сохранены; точные повторы уже выполненных отгрузок не создают нового эффекта. Прошли 216/216 проверок в 13 классах без пропусков, включая HTTP/PostgreSQL переход `PENDING → CONFIRMED`, отсутствие допуска при `NULL`, резервы, оплату, отгрузки, возвраты, инвентаризацию и канонические контракты. YAML разобран; структура схем и wire-поля не менялись. Публикация и изменение данных не выполнялись.

5. **R-006 — регистрация смен до эффектов отгрузки.** Точная квитанция проверяется без блокировки, записи и построения ответа. Новый план с неоплаченным или отсутствующим заказом либо недопустимыми параметрами расписания отклоняется до регистрации; затем регистрируются все нужные смены, после чего выполняются replay/create и актуальные проверки отдельных частей. Отказ первой или второй регистрации не добавляет локальных отгрузок, строк, заданий, квитанций, admission и событий; повтор сохраняет ключи и идентификаторы. Проверены 153 различных сценария в восьми классах: 141 прошёл в основном запуске, ещё 12 — после точечных исправлений новых тестовых фикстур; пропусков нет. Проверки сопоставлялись по фактическим XML и логам, production-код после основного запуска не менялся. OpenAPI YAML разобран, структура маршрутов, ответов и схем вне описаний сохранена. Публикация не выполнялась.

6. **R-007 — полное имя контакта планировщика.** Четыре DTO и колонка БД согласованы с пределом владельца 512 символов; публичный OpenAPI пересоздан, генерация TypeScript не дала изменений. Все 84 теста прошли: Cyrillic 200/201/255/512 и отказ на 513, HTTP feed с нормальным соседним заказом, сохранение и version-fenced изменение, upgrade 0034→0035 и отказ от потери длинного имени при downgrade. Использовалась отдельная PostgreSQL/PostGIS БД; временный контейнер удалён. Ruff прошёл. Исправлена только новая тестовая проверка nullable OpenAPI после первого запуска.
7. **R-014 — номер в снимке asset для maintenance.** Каноническая схема требует существующий номер бытовки длиной 1–128 символов. Реальный авторизованный MockMvc-ответ проверен по этой схеме: положительный результат, верхняя граница и отказ на missing/null/empty/129. Потребитель сохраняет точный номер. Семь тестов прошли без пропусков; production Java и БД не менялись.
8. **R-012 — событие начала отмены перемещения.** Существующее событие добавлено в регистрацию безопасного publisher, схему, каталог и whitelist dossier. Проверены реальный зарегистрированный publisher/relay, malformed/key/status rejection и PostgreSQL journal/inbox/checkpoints при повторной доставке; событие не создаёт activity бытовки без её идентичности. Все 87 тестов прошли без пропусков. До исправления отказ был возможен ещё у producer validator, поэтому исходное описание DLT не означает доказанную доставку до dossier. Replay и backfill не выполнялись.
9. **R-010 — приёмка перемещения в Manager.** До фотографий выполняется preflight с исходными версиями. Отсутствующие очереди и ошибки блокируют приёмку; продолжение ремонта требует явного приоритета 1–5, без ремонта передаётся null. Фоновая очередь восстанавливает этот выбор вместе с версиями, медиа и ключом. Закрытие, смена склада/учётной записи и устаревшие версии защищены проверками актуальности. Все 60 тестов прошли без пропусков: 11 coordinator, 3 Compose UI, 1 warehouse date, 21 HTTP, 11 boundary и 13 store. Первоначально исправлен неверный импорт в новом тесте; production компиляция проходила. Собран локальный debug APK `dev.buhanzaz.rwms.manager.debug` версии `55 / 0.3.52-debug`, SHA-256 `867bdad9e7ae176951ed51c42b116ed7010099a4731e4669496df93815421b06`; APK не публиковался.

10. **R-008 — полный дневной статус назначений.** Убрано только ограничение чтения в 500 элементов; командные ограничения сохранены. Все 56 тестов прошли на отдельной мигрированной PostgreSQL/PostGIS БД, включая HTTP-выдачу 501 записи и совпадение задачи после первых 500. Временный контейнер удалён.
11. **R-015 — plannerLineage внешней задачи.** Контракт описывает действующий optional nullable объект из четырёх обязательных полей. Проверены реальные сериализация и регистрация, сохранение всех полей и запрет изменённого replay. 7 task-board и 53 logistics теста прошли без пропусков.
12. **R-013 — полная REST-граница auth.** Добавлены 14 уже работающих операций; auth runtime не менялся. Пройдены 28 contract-тестов, 31 незатронутая integration-проверка и финальный прогон всех 14 authorization-вариантов. Новые тесты исправлены по реальному HTTP: пропуск primitive checkpoint даёт 400, а Mock JWT principal разрешается по username. Отдельно подтверждён существующий 500 при отсутствующем shadow checkpoint — R-137, пока не исправлен. Начальные ошибки нового test setup/import не относятся к production.
13. **R-084 — восстановление частичной загрузки Panel.** Каждый успешный finalize сохраняет серверный ID до завершения соседей; любой завершённый пакет обновляет owner query. Retry использует прежние file/folder/sort/idempotency keys, успешные файлы не повторяются. Создание владельца не размонтирует незавершённый пакет; его выбранные media и обложка переходят в галерею. Все 27 тестов прошли, включая реальный hook/очередь/диалог с частичным успехом, незапущенным пятым файлом, удалением неудачного файла и созданием владельца. TypeScript, scoped ESLint и production build прошли. Существующее предупреждение сборки о размере chunks осталось; публикации не было.

14. **R-016 — фактическая аудитория доски.** По явному решению пользователя удалены только нереализованные `audienceSelectors` из RouteStepRequest и BoardEntry. Queue bindings и эффективные selectors WorkerTaskDetail сохранены. 11/11 тестов прошли без пропусков, включая созданную задачу и авторизованный HTTP JSON, проверенный по закрытой канонической схеме.
15. **R-017 — стабильная квитанция asset outbox.** Ответ содержит идентичность события/агрегата, версию агрегата, `state=PENDING` и принятые review version/time. Точный повтор после публикации возвращает ту же квитанцию, не меняя PUBLISHED в БД. Все 10 тестов прошли без пропусков, включая canonical JSON и PostgreSQL replay; хранение и схема БД не менялись.
16. **R-018/R-019 — соответствие logistics DTO и канонических схем.** Readiness описывает все три обязательных флага и отсутствие задания; Panel показывает это состояние без запроса/ссылки с null ID. Подтверждение презентации описывает действующий выбор 1–120 месяцев для каждой бытовки либо один общий срок. Прошли 15 service-тестов readiness, 32 contract-теста и интеграционный сценарий двух бытовок со сроками 2/6, частичным некорректным набором и replay. Последний сценарий повторён после исправления новой replay-фикстуры; 47 уже успешных проверок не запускались заново. 52 теста Panel, TypeScript, scoped ESLint и verifyCanonicalContracts прошли; production Java logistics и БД не менялись. Публикации не было.

17. **R-076 — отмена исходящего SSE exchange.** Header timeout завершается на отдельном future и отменяет исходный HTTP-запрос; позднее тело подписывается только для отмены. Все 12 gateway-тестов прошли: управляемые timeout/cancel/late-body, существующий lifecycle и loopback HTTP с 504, реальным EOF сокета и повторным подключением при лимите одного потока. Production после проверки не менялся; новая тестовая вспомогательная функция даёт compile warning об unchecked generic Mockito mocks.
18. **R-078 — назначение очереди при замене маршрута.** Existing purpose policy применяется по сохранённому TaskSyncSource до мутации. Maintenance не может перейти в очередь водителей, logistics driver task — в обычную очередь. Новый integration-сценарий сохраняет версии, полные route entries и число событий; два существующих сценария проверяют корректную замену, канонический порядок и replay. Все 3 теста прошли без пропусков.
19. **R-081 — сохранение одновременного SSE reconnect.** Регистрация и очистка последнего подписчика выполняются внутри per-key compute обоих hubs, сохраняя warehouse/surface/worker isolation. Все 6 тестов прошли без пропусков. Барьерные тесты приостанавливают реальный зарегистрированный cleanup callback, затем проверяют доставку новому соединению; production test hooks не добавлялись.
20. **R-093 — актуальный адрес проверки слота.** Новый ввод, выбор подсказки, ручные координаты, точка карты и закрытие отменяют прежний lookup; игнорируются его поздние success/error, а актуальная ошибка остаётся видимой. Пройдены 16 тестов формы с управляемыми Promise, включая обратный порядок ответов и отсутствие расчёта для старого адреса. TypeScript и scoped ESLint прошли после исправления require-await в новых тестах. Публикации не было.
