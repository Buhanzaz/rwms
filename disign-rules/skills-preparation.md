## Как применять

1. Начать с [правил владельца](design-rules.md) и конкретных замечаний аудита. Главный ориентир — премиальный и удобный магазин с одобренными градиентными кнопками.
2. Использовать уже имеющийся `frontend-design` для выразительной композиции, материалов, света, глубины и типографической иерархии. Подготовить согласованные образцы входа, карточки, фильтров, корзины и заказа в обеих темах.
3. Использовать `ui-ux-pro-max` для проверки конкретного решения и состояний. Его рекомендации адаптировать к кириллице, аренде бытовок и реальным данным; результаты поиска не считать готовым макетом.
4. Для реализации Android использовать мобильный навык вместе с уже доступными `adaptive`, `edge-to-edge` и `android-cli`. Системную палитру Material You не включать автоматически: цвета бренда, карты и кнопок уже определены владельцем.
5. Использовать iOS-навык как проверку пригодности дизайна для iPhone. Он не означает миграцию текущего Android-приложения на SwiftUI и не заменяет будущую проверку на iPhone.
6. Проверять результат по критериям конкретного замечания и реальному сценарию; не объявлять дизайн премиальным только по имени установленного навыка.

**Приоритет сохраняется:** текущая команда владельца → AGENTS.md → контракты и владелец домена → [правила дизайна](design-rules.md) → рекомендации навыков. Навык не разрешает менять одобренные кнопки на круглые стандартные, делать модальные поверхности прозрачными, перекрашивать карту, вводить ручное обновление, подставлять фиктивные товары/цены или переносить бизнес-логику в UI.

Скрипт поиска установлен локально; вызывать по фактическому пути, а не по примеру с переменной Claude:

```bash
python3 /root/.codex/skills/ui-ux-pro-max/scripts/search.py \
  'color dark mode contrast' --domain ux

python3 /root/.codex/skills/ui-ux-pro-max/scripts/search.py \
  'semantics' --stack jetpack-compose
```

Поиск не требует внешней отправки данных проекта. Автоматическая запись новой дизайн-системы не запускалась: согласованные правила уже находятся в этой папке.
