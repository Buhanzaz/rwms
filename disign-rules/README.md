# RWMS Customer: аудит UI и UX

Проверка клиентского магазина аренды бытовок **6 сентября 2026 года**. Здесь собраны найденные проблемы, оригинальные скриншоты, решения владельца продукта и задания на будущие исправления. Это результат аудита; изменения интерфейса ещё не реализованы.

Главная проблема — отсутствие единого визуального языка между входом, каталогом, корзиной, доставкой и заказами. Дополнительно обнаружены проблемы компоновки с клавиатурой, поведения фильтров, читаемости действий и тёмной темы. Удачный образец уже есть: владелец одобрил оформление кнопок входа и регистрации и просит распространить его на приложение.

## Достоверность и приоритет

| Метка | Значение |
| --- | --- |
| **Телефон** | Экран или взаимодействие проверены на подключённом физическом устройстве. |
| **Владелец** | Явное требование или сообщение владельца во время совместного обхода. Если независимого воспроизведения нет, это указано. |
| **Код** | Факт или риск найден в текущей реализации; непроверенный сценарий не выдается за выполненный тест. |
| **P1** | Исправить в первую очередь: мешает основному сценарию, пониманию заказа или нарушает явно заданное поведение. |
| **P2** | Следующий приоритет: качество подачи, последовательность и удобство. |

P0 — доказанного аварийного дефекта с потерей данных или реальным списанием денег — этот обход не выявил. Это не заключение об отсутствии подобных дефектов вне проверенного сценария.

## Приёмка будущей реализации

- Пройти тот же маршрут: вход → город → фильтры → фотографии → корзина → доставка → подтверждение → заказ.
- Проверить конкретные критерии в каждом замечании, включая отрицательные сценарии: нулевая выдача, ошибка сети, недоступная цена, конфликт резерва и истечение времени.
- Сверить единые компоненты в светлой и тёмной темах, с клавиатурой, длинным адресом и длинным названием типа.
- Проверить ширины 360–430 dp и увеличенный системный шрифт; iPhone проверить отдельно, когда будет доступна соответствующая реализация.
- Использовать тесты затронутых Compose-компонентов и политик, затем проверку на реальном устройстве. Сборка APK сама по себе не подтверждает UX.
- Для этого документального изменения проверяются ссылки, изображения и чистота diff. Сборки и тесты приложения не запускались: прикладной код и развёрнутые артефакты не изменены. Создание заказа и тестовая оплата описаны отдельно выше.
