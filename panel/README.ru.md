# Панель RWMS

`panel/` — React/TypeScript веб-панель для операционных пользователей RWMS.
Это браузерный клиент, а не фасад доменных сервисов: бизнес-команды,
авторизация, переходы состояния и хранение остаются у владеющих backend-сервисов.

English version: [README.md](README.md).

## Публичная граница и аутентификация

- Браузер обращается только к публичному API gateway на собственном origin:
  `/auth/**` для OAuth/OIDC и `/api/**` для публичных API. В конфигурации не
  должно быть внутренних адресов сервисов, service-port на `localhost` или
  маршрутов `/api/internal/**`.
- Интерактивный вход использует OIDC-flow gateway. Панель принимает человека с
  principal `USER`; gateway и владеющий сервис всё равно проверяют каждую роль
  и доступ к складу. Скрытие UI-контрола не является авторизацией.
- Vite proxy — только удобство локальной разработки. В production запросы
  браузера остаются same-origin и должны обслуживаться публичным gateway.

## Продуктовая поверхность и владение состоянием

Роутер открывает операционную панель склада/оборудования, аренды и заказов,
инвентаризации, обслуживания/приёмки, логистики, доски задач, ассистента,
списаний и настроек. Текущий профиль пользователя определяет доступные
контексты складов и экраны.

- TanStack Query хранит серверные чтения; query keys включают нужные склад,
  сущность и параметры фильтра. Авторитетным остаётся сервер.
- Выбранный склад — неавторитетное локальное UI-предпочтение. После входа он
  перепроверяется по профилю.
- Проверенный аутентифицированный subject и его bearer grant revision владеют
  отдельным вложенным TanStack Query client. Logout, смена subject или grant
  перемонтируют защищённый subtree и тем самым останавливают effect-owned
  realtime streams, отменяют и удаляют защищённые query и mutation state и
  очищают media blob URL до монтирования следующего защищённого subtree.
  Корневой client сохраняет public offer и bootstrap state.
- SSE потоков assets и media — это invalidation-сигналы, а не вторая доменная
  проекция. Их обработчики обновляют или patch-ят только затронутые query и
  удаляют media blob с изменённой ревизией; глобальной очистки cache нет.
- Досье бытовки принимает полный канонический словарь activity. Подготовка и
  завершение передачи ремонта отображаются в истории ремонта с immutable
  snapshot склада, возвращённым `dossier-service`; точную границу задают
  [OpenAPI dossier](../contracts/openapi/dossier-service.yaml) и строгая
  [модель activity панели](src/features/rental-items/dossier/model/dossier-service.ts).
- Панель может объединять независимые публичные чтения для экрана, но не должна
  оркестрировать межсервисные бизнес-процессы в браузере.

## Ассистент аренды, клиенты и заказы

- Карточки уточнений ассистента — долговечные серверные данные. Независимые
  ветки, например ОСБ и ЛДСП, можно отвечать отдельно и в любом порядке; панель
  показывает понятный вид вопроса и только точные варианты сервера. Карточки
  результата требуют одновременно тип бытовки и отделку, а точные последующие
  фильтры берутся из результата поиска, а не угадываются браузером. См.
  [OpenAPI ассистента](../contracts/openapi/assistant-service.yaml), строгий
  [адаптер ассистента](src/features/assistant/api/assistant-api.ts) и
  [страницу диалога](src/features/assistant/pages/assistant-page.tsx).
- Выборкой ассистента и сроком её блокировки владеет логистика. Снятие checkbox
  отправляет полный оставшийся набор ID с idempotency key; пустой набор
  освобождает hold, а частичное удаление применяет новый авторитетный срок.
  Потоковое удаление по команде LLM согласуется сразу, после чего terminal
  refetch перечитывает диалог. Браузер никогда не считает локальный набор
  checkbox авторитетным состоянием.
- Навигация аренды открывает `/clients/new`, `/clients` и
  `/clients/:clientId`. Форма требует тип клиента, наименование/ФИО и телефон,
  дополнительно требует контактное лицо для ИП или юридического лица и явно
  показывает аутентифицированного ответственного менеджера как read-only
  значение, которым владеет сервер. Grid клиентов получает серверные страницы;
  карточка клиента читает его заказы и ведёт в чат, подбор по складу или ручное
  создание заказа, передавая для prefill только `clientId`. Исторический клиент
  с правдивым `null` вместо телефона показывается как «не указан» и никогда не
  дополняется вымышленным значением в браузере. См.
  [OpenAPI логистики](../contracts/openapi/logistics-service.yaml) и
  [feature клиентов](src/features/clients/).
- Экраны создания/редактирования заказа сохраняют адрес доставки, широту,
  долготу, изменяемый контактный телефон, комментарий и конкретные допустимые
  даты приёмки. Списки и детали показывают эти серверные проекции. Деталь заказа
  показывает принадлежащие логистике плановые/фактические отвозы и возвраты,
  затем независимо читает публичное досье выбранных бытовок. Отсутствие сметы
  или ремонта считается доказанным только после полного чтения всех страниц
  проекции досье; partial, ошибочное или ещё не завершённое постраничное чтение
  явно остаётся неопределённым. См. [адаптер заказов](src/features/orders/api/orders-api.ts)
  и [доказательства досье](src/features/orders/components/order-unit-dossier-evidence.tsx).

## Ошибки, конкурентность и команды

Общий bearer-клиент преобразует gateway Problem Details в `ApiError` с HTTP
статусом и машиночитаемым кодом. Отсутствующая сессия, недоступный gateway или
неподдерживаемая публичная операция показываются как явная ошибка; mock-success
fallback отсутствует.

Обычные HTTP-запросы ассистента и stream turn ассистента используют одно
безопасное преобразование Problem Details. `401` остаётся сигналом
обновления аутентификации/повторного входа, `403` требует обновлённых grants
или действия пользователя, а `409` требует авторитетного пути
refetch/conflict. Некорректное тело Problem Details всё равно возвращает
`ApiError` со статусом и безопасным fallback-сообщением.

Для изменяющих операций используйте fencing, заданный канонической OpenAPI
операцией (`expectedVersion`, ETag или эквивалент), и единый путь
refresh/retry для `409 Conflict`. Повторяемые create/effect требуют
idempotency key контракта или стабильный внешний идентификатор. Не делайте вывод
об успехе команды только по обновлению cache или SSE-уведомлению.

## Локальная разработка и проверки

Из этого каталога с актуальной Node.js LTS:

```bash
npm ci
npm run dev
npm run typecheck
npm test
npm run lint
npm run build
```

`npm run dev` слушает `localhost:8080`; его proxy target предназначен только
для локальной разработки. До заявления об интеграции или релизе настройте и
проверьте настоящий публичный gateway origin.

## Правила релиза

Собирайте только из целевого reviewed source scope. Release bundle нужно
проверить через same-origin `/auth/**` и `/api/**`: первый вход,
чтение профиля/workspace, разрешённую команду, путь `409` где он применим и
обновление по invalidation. Нельзя публиковать артефакт, собранный из другого
checkout или смешанного непроверенного worktree.

## Текущие ограничения

- Защищённые серверные данные и media blob должны оставаться внутри client
  boundary ревизии. Не добавляйте browser store, unscoped object-URL cache или
  прямую запись защищённого state в root client: они обходят fence subject и
  grant.
- Streaming path ассистента разделяет преобразование Problem Details обычного
  bearer-клиента; не добавляйте вторую политику статусов или тела ошибки.

## Источник истины

Семантика публичных операций находится в `contracts/openapi/`, семантика
событий — в `contracts/events/`. Gateway владеет маршрутизацией и проверкой
токена, но не бизнес-агрегацией. UI-изменения проверяйте одновременно с
владеющим сервисом и каноническим контрактом.

Общая граница failures реализована в
[`src/lib/api-client.ts`](src/lib/api-client.ts), а stream ассистента использует
её из [`src/features/assistant/api/assistant-api.ts`](src/features/assistant/api/assistant-api.ts).
