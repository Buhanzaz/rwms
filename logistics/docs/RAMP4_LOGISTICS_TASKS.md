# RAMP 4 — логистика: сводная раскидка

## Границы работы

В этот план входит только `logistics/`. Менеджерское и рабочее Android-приложения не меняются. Водительский выбор прицепа поэтому остаётся отдельной задачей мобильного приложения после согласования его контракта с логистикой.

## Блок A — модель и владение данными

### L-10. Одна компания

**Цель:** убрать модель мультикомпанийности, если она ещё существует в владельцах данных, контрактах или миграциях.

**Готово сейчас:** в проверенном интерфейсе Logistics нет переключателя или фильтра компании.

**Осталось:** отдельно проверить владеющий сервис и миграцию данных; не удалять данные/поля без известного владельца и плана переноса.

**Критерий готовности:** все складские, транспортные и рейсовые запросы работают в одном подтверждённом контексте компании без скрытого второго источника данных.

### L-11. Независимые сущности

**Цель:** зафиксировать модель `Склад → водители / наёмники → автомобили → прицепы → рейсы → задания`.

**Сделано в UI:** автомобиль и прицеп уже отдельны; прицеп больше не задаётся в основной карточке автомобиля.

**Осталось:** закрепить назначение прицепа в контракте рейса и в DriverApp. Это намеренно не включено в текущий diff, потому что приложения исключены из задачи.

### L-12. Связь с RWMS

Фраза «убрать полностью» требует отдельного продуктового решения. Сейчас RWMS — источник учётной записи, заказов клиента и части защищённых логистических действий; простое удаление интеграции сломает авторизацию и получение параметров заказа. В UI убраны неоператорские RWMS-поля там, где это не меняет владельца данных.

**Решение перед началом:** определить замену для SSO, заказа клиента, каталога груза и передачи заданий, либо уточнить, что требуется только убрать терминологию из интерфейса.

## Блок B — склад и заявки

### L-13. Склад как единый контекст

- Везде использовать единый формат имени склада.
- В настройках показывать компактную строку `город — адрес — timezone`.
- Не показывать технические ID, `Источник` и «корень планирования» оператору.

**Остаток:** пройти остальные незатронутые экраны и заменить старые подписи только после подтверждения, что они не являются диагностикой для администратора.

### L-14. Заявка получает груз из заказа

- Логист не вводит массу и габариты бытовки вручную.
- Экран показывает параметры, пришедшие из заказа, и сохраняет их при редактировании.
- Для новой ручной заявки требуется владелец связи с заказом клиента: не следует придумывать физические параметры в Logistics.

**Критерий готовности:** попытка назначить заказ без полного профиля груза возвращает понятную причину вместо вымышленного значения.

### L-16. Наёмники и компании-наёмники

**Нужен контракт task-board:** текущий контракт наёмника содержит только отображаемое имя, телефон, комментарий, активность и тип занятости. В нём нет компании, раздельных ФИО, госномера и признака прицепа.

После изменения владельцем контракта выполнить один вертикальный блок:

1. компания, привязанная к городу склада;
2. список водителей компании и отдельный список наёмников без компании;
3. «Добавить водителя» в компанию;
4. поля имени, телефона, номера автомобиля и «С прицепом»;
5. миграция существующих профилей без записи новых данных в поле комментария.

## Блок D — транспорт и параметры маршрута

### L-18. Упрощённый транспорт

Карточка автомобиля: название, марка, госномер, вместимость одной машины, грузоподъёмность и габариты. Прицеп: марка и госномер. Технические параметры расчёта остаются в закрытом разделе и не теряются при сохранении.

**Осталось:** перенести средние скорости в общие настройки, если владелец маршрутизации подтвердит единый источник этих значений.

## Общие правила приёмки

1. Оператор выбирает бизнес-сущность; физические параметры приходят от владельца заказа.
2. Склад всегда виден в одном формате, без технических идентификаторов.
3. Водитель, автомобиль и прицеп — независимы.
4. Общий DatePicker применяется вместо нативных полей даты.
5. Новые кнопки появляются только вместе с реальной командой владельца данных.
6. Для каждого изменения запускать затронутые frontend/backend/contract тесты; Android в этой инициативе не изменяется.
