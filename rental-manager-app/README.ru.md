# RWMS Менеджер аренды для Android

`rental-manager-app/` — отдельное Android-приложение менеджеров аренды. Оно намеренно отделено от
складского ManagerApp в `app/` и не использует его пакет, OAuth-клиент, scopes, страницу загрузки
или складские процессы.

English version: [README.md](README.md).

## Текущий рабочий срез

- Нативный вход через публичный gateway по OAuth Authorization Code + PKCE S256.
- Серверная проверка `USER`, `RENTAL_MANAGER`, `rentalAccess=true` и явных складских grants.
- Справочник складов единой инсталляции RWMS с явным состоянием, когда склады не назначены.
- Реальные поиск, пагинация, карточка и идемпотентное создание клиента в logistics-service.
- Реальные поиск, пагинация и карточка заказа, создание черновика и version-fenced изменение
  разрешённых сервером полей.
- Существующая история диалогов assistant-service, создание диалога для существующего клиента,
  архивирование, текстовые turn и единственный актуальный вопрос-уточнение. SSE-события строго
  проверяются и ограничиваются; после транспортной ошибки turn POST не повторяется.
- Актуальные результаты поиска бытовок, структурированные сообщения о нехватке и текущая
  принадлежащая logistics-service подборка с резервом. Менеджер может убрать точные бытовки или
  освободить весь резерв, затем опубликовать точную группировку через logistics-service и явно
  скопировать либо отправить публичную ссылку. При неизвестном результате и конфликте команды
  сохраняют actor-scoped Idempotency-Key и перечитывают серверное состояние.
- Карточки выбранных бытовок показывают актуальные месячные цены logistics из точных строк целых
  рублей. Цены перечитываются при смене подборки, возврате на экран и явном обновлении.
  Отсутствующая цена или ошибка остаётся недоступностью; проверки пользователя, диалога, склада и
  номера запроса не дают старому ответу подменить другую подборку или новый тариф. Чтения не меняют
  резервы и не фиксируют коммерческие условия.
- Ответ отправленного представления сохраняет точную цену и ревизию тарифа, зафиксированные
  владельцем. Историческая пара null остаётся неизвестной ценой; неполная пара или числовой
  JSON-токен вместо точной строки суммы отклоняется.
- Редактируемый черновик или сохранённый заказ открывает единственный диалог assistant-service,
  связанный именно с этим заказом. Повторное открытие использует серверный диалог и не создаёт
  дублирующую заявку.
- Карточка заказа показывает актуальные выбранные бытовки, заказанное наполнение и сроки аренды
  из logistics-service с русскими статусами и датами; транспортные UUID и enum не отображаются.
- Редактируемый черновик можно отменить только после явного подтверждения. Android передаёт
  текущую версию заказа и сохраняемый идемпотентный ключ; logistics-service освобождает активные
  резервы бытовок, записывает историю и возвращает актуальное отменённое состояние.
- Карточка готовности показывает точные серверные данные, которых ещё не хватает. Сохранение
  заблокировано, пока нет контакта, подтверждённых клиентом адреса и дат, склада, выбранных
  бытовок и срока каждой аренды; version-fenced команда принимает только ответ сервера.
- Нижняя навигация на телефоне и автоматический navigation rail на широком окне через Material 3
  adaptive navigation для «Чат», «Клиенты» и «Заказы». В интерфейсе нет операций RWMS,
  диспетчерской логистики и админки.

Для претензий сначала необходим канонический API владельца. Android показывает черновик
сохранённым только после принятой logistics-service version-fenced команды: поля менеджера
остаются полями черновика, а бытовки, сроки аренды и подтверждённые клиентом адрес и даты доставки
поступают через существующий связанный контур заявки/представления, которым владеет backend.

## Безопасность и транспорт

- Пакет: `dev.buhanzaz.rwms.rentalmanager`.
- OAuth-клиент: `rwms-rental-manager-android`.
- Точный application scope: `rental.manage` (вместе с `openid profile offline_access`).
- HTTPS callback: `/auth/rental-manager/callback` на `RWMS_PUBLIC_BASE_URL`.
- В приложение не встраиваются browser- или internal-адреса сервисов. Все runtime-вызовы идут
  через `/auth/**` и `/api/**` публичного gateway origin.
- AuthState шифруется AES-GCM с ключом Android Keystore. Финальный `401` инвалидирует локальную
  сессию; временная ошибка refresh сохраняет её.
- Повторяемая команда сохраняет стабильный UUID, а в Android saved state попадает только SHA-256
  fingerprint запроса, привязанный к проверенному subject менеджера. Телефон, email, имена и
  комментарии в fingerprint не хранятся. Идентификатор создания диалога сохраняется между
  неудачными попытками того же пользователя и запроса; замена подборки и публикация представления
  и сохранение либо отмена черновика сохраняют точный Idempotency-Key, пока серверный результат
  не подтверждён.
- Клиент assistant turn покрывает ограниченное 120-секундное окно SSE сервиса и отключает как
  сетевой повтор, так и повтор после refresh токена для неидемпотентного turn POST. Финальный
  `401` вместо этого инвалидирует общую зашифрованную сессию.
- Release-задачи закрыты без внешнего защищённого signing properties файла. Существующий
  `manager-download-site/` принадлежит складскому ManagerApp и не должен перезаписываться.

## Проверка

Из корня репозитория:

```bash
./app/gradlew -p rental-manager-app --no-daemon --max-workers=2 \
  -Pkotlin.compiler.execution.strategy=in-process \
  testDebugUnitTest assembleDebug
```

Debug APK создаётся здесь:

`build/outputs/apk/debug/rwms-rental-manager-app-debug.apk`

Успешная сборка сама по себе не означает публикацию APK.
