# Актуальные знания о проекте RWMS

[English version](README.md)

Этот каталог — поддерживаемая навигационная карта текущего продукта RWMS. Он
фиксирует устойчивую архитектуру, владение, бизнес-инварианты, расположение
контрактов и значимые изменения, чтобы будущие задачи быстро находили
авторитетные источники.

Он не заменяет OpenAPI/event schemas, Flyway migrations, domain code или
tests. Каждое утверждение здесь должно проверяться по этим источникам.

## Иерархия источников

Используйте порядок источников из [`AGENTS.md`](../../AGENTS.md). В частности:

- канонические HTTP- и event-границы находятся в
  [`contracts/`](../../contracts/);
- бизнес-переходами владеет соответствующий сервис в
  [`services/`](../../services/);
- форма и эволюция БД находятся в Flyway-каталоге каждого сервиса;
- этот каталог объясняет и индексирует подтверждённые факты;
- [`docs/plans/`](../plans/) и
  [`WMS_ARCHITECTURE_KNOWLEDGE/`](../../WMS_ARCHITECTURE_KNOWLEDGE/) — только
  исторические свидетельства.

Если этот каталог противоречит актуальному авторитетному источнику, исправьте
каталог. Если авторитетные источники противоречат друг другу или запросу
пользователя, занесите конфликт в `open-questions.md` и запросите решение.

## Использование в задаче

1. Читайте только относящиеся к задаче страницы базы знаний.
2. Проверяйте их утверждения по актуальным контрактам, коду, миграциям и тестам.
3. Реализуйте и проверьте запрошенное изменение.
4. Обновляйте соответствующую страницу при изменении архитектуры, владения,
   доменной логики или контракта.
5. Добавляйте краткую строку в change log с источниками и проверками.

Используйте `Confirmed` только для поведения, подтверждённого текущим
репозиторием. Нереализованные проекты помечайте `Proposed` и не считайте их
разрешением на разработку. Нерешённые варианты помещайте в
`open-questions.md`.

Не храните здесь secrets, credentials, production endpoints, сведения о
клиентах, полные копии схем, generated output или временные отладочные заметки.
